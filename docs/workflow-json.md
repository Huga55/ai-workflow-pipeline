# Workflow JSON

Этот файл — инструкция для модели, которая собирает или правит workflow. Ответ должен быть одним JSON-объектом. Без пояснений вокруг, без комментариев внутри JSON, без лишних полей и без висячих запятых. Отступ — два пробела.

Если правишь уже существующий workflow, на входе будет его JSON. Меняй только то, что просили. Поля `id` не выдумывай и не переписывай: если они уже есть, оставь как есть. Если собираешь workflow с нуля, поля `id` не пиши вообще.

Связь между шагами — это поле `key`, а не `id`. В `dependsOn` и в похожих ссылках указывай `key` другого шага.

## Зачем это

Workflow — граф, а не жёсткий список. Шаг выполняется, когда выполнены шаги из `dependsOn`. Результат шага доступен следующим как `{{steps.КЛЮЧ.output}}`.

Корень:

```json
{
  "name": "Название workflow",
  "description": "Коротко, что он делает",
  "inputs": [],
  "snippets": [],
  "steps": []
}
```

`name` и `description` — строки. Пустую строку можно опустить, но лишние поля в корне писать нельзя. `snippets` можно не писать, если фрагментов нет.

## Основа

Поле `runtime` в корне говорит, как workflow разговаривает с моделью.

| Значение | Смысл |
| --- | --- |
| нет поля или `api` | Каждый AI-шаг сам отправляет все свои `messages` в API провайдера |
| `playwright` | Перед шагами открываются чаты Qwen в браузере. Шаг только дописывает новый текст в уже открытый чат |

В одном workflow режим один. Для другой основы сделай копию workflow.

У `playwright` в корне есть массив `chats`. Каждый чат создаётся заново на новом запуске и на «Запустить заново». Повтор шага внутри того же запуска пишет в уже открытый чат.

```json
"runtime": "playwright",
"chats": [
  {
    "key": "analyst",
    "scope": "run",
    "instruction": "Ты разбираешь упаковку. Не выдумывай логотипы.\nФото:\n{{inputs.product_image}}"
  },
  {
    "key": "shots",
    "scope": "branch",
    "instruction": "Ты предлагаешь кадры для одной концепции. Продукт не переделывай."
  }
]
```

| Поле | Смысл |
| --- | --- |
| `key` | Имя чата. Такое же, как `config.chat` у шага. Латиница, цифры и `_` |
| `instruction` | Первое сообщение чата. Уходит один раз. Можно подставлять `{{inputs...}}`, фрагменты и фото |
| `scope` | `run` — один чат на весь запуск. `branch` — свой чат в каждой ветке, создаётся когда ветка начинается. По умолчанию `run` |

`scope: "run"` создаётся в начале запуска, до шагов. В инструкции ещё нет результатов шагов. `scope: "branch"` создаётся в начале ветки, поэтому в инструкции уже есть элемент ветки, например `{{current_item}}`.

## Идентификаторы

У входа, шага и сообщения модели есть `id`. Его хранит приложение, по нему запускам видно, что это тот же шаг.

- Не придумывай `id` сам (`"1"`, `"step1"`, случайный набор символов).
- В новом workflow поле `id` не пиши. При сохранении приложение создаст свой идентификатор.
- Если шаг с таким `key` уже был, приложение оставит прежний `id`, даже если в JSON его нет или вместо него стоит выдуманный.
- Если `id` уже стоит в присланном JSON, не меняй его. Смена `id` для запуска выглядит как удаление старого шага.
- `key` тоже не меняй без просьбы: запуск помнит шаг и по `id`, и по ключу.

`key` и `name` входа — идентификаторы в тексте: латиница, цифры и `_`, первый символ не цифра. Примеры: `topic`, `product_image`, `shot_review`. Пробелы, дефисы и кириллица в ключе нельзя. Человеческое название живёт в `name` у шага и в `label` у входа.

## Входы

Вход — то, что человек заполняет перед запуском. Шаги читают его как `{{inputs.ИМЯ}}`.

```json
{
  "name": "topic",
  "label": "Тема",
  "type": "text",
  "required": true,
  "description": "О чём писать"
}
```

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `name` | да, либо его можно вывести из `label` | Имя в `{{inputs.topic}}` |
| `label` | нет | Подпись в форме. Если пусто, берётся `name` |
| `type` | нет, по умолчанию `string` | Тип значения |
| `required` | нет, по умолчанию `false` | Пустой обязательный вход останавливает шаг, который его читает |
| `description` | нет | Подсказка человеку |
| `defaultValue` | нет | Значение, если человек ничего не ввёл |
| `options` | для `select` и `multi-select` | Массив строк, варианты выбора |

Типы `type`:

| Значение | Что вводит человек |
| --- | --- |
| `string` | Короткая строка |
| `text` | Длинный текст |
| `number` | Число |
| `boolean` | Да или нет |
| `image` | Одно изображение |
| `image[]` | Несколько изображений |
| `file` | Один файл |
| `file[]` | Несколько файлов |
| `json` | JSON-значение |
| `json[]` | Массив JSON-значений |
| `select` | Один вариант из `options` |
| `multi-select` | Несколько вариантов из `options` |

У `select` и `multi-select` массив `options` не должен быть пустым.

## Общие поля шага

```json
{
  "key": "summary",
  "name": "Пересказ",
  "description": "",
  "type": "ai",
  "order": 1,
  "dependsOn": [],
  "stopAfter": false,
  "iterate": null,
  "config": {}
}
```

| Поле | Смысл |
| --- | --- |
| `key` | Имя в `{{steps.summary.output}}` и в ссылках. Если нет, берётся из `name` |
| `name` | Название в интерфейсе. Нужен `key` или `name` |
| `description` | Заметка, на запуск не влияет |
| `type` | Вид шага, см. ниже |
| `order` | Порядок на схеме. Если нет, это позиция в массиве, начиная с 1 |
| `dependsOn` | Массив ключей шагов, которые должны закончиться раньше. Пустой массив — шаг ни от кого не ждёт |
| `stopAfter` | `true` — после шага запуск останавливается, пока его не продолжат |
| `iterate` | Обычно `null`. Ветвление массива лучше делать шагом `fanout` |
| `use` | Ключ другого шага. Тогда `type` и `config` берутся от него |
| `sideBranch` | `true` — доп. ветка: рамка у шага, от которого она зависит. В запуске одна цепочка от этого шага, вложенное ветвление дальше по списку её не копирует |
| `config` | Настройки этого типа. У `fanout` можно не писать, это пустой объект. При `use` поле `config` не пиши |

Ключи шагов не повторяются. `dependsOn` не должен замыкать цикл: если A ждёт B, B не может ждать A ни напрямую, ни через цепочку.

### Доп. ветка (`sideBranch`)

Для отдельного пути рядом с основным (например доп. шоты от концепта). Ставь `sideBranch` на **первый** шаг цепочки. Шаги, которые зависят только от него и дальше по этой цепочке, идут вместе с ним.

Цепочка крепится к шагу из `dependsOn`. Если таких шагов несколько, в схеме берётся тот, что ниже в основной колонке. В запуске линия идёт от шага с наибольшим `order` среди этих зависимостей, и цепочка выполняется один раз в его ветке. Вложенный fanout, который стоит дальше по списку, эту цепочку не забирает: доп. шоты от элемента концепции не повторяются на каждом кадре.

Ожидание в доп. ветке не останавливает основную цепочку той же ветки. Пауза основной цепочки не откладывает доп. ветку.

```json
{
  "key": "extra_brief",
  "name": "Указания для доп. кадров",
  "type": "manual",
  "sideBranch": true,
  "dependsOn": ["each_concept"],
  "config": { "mode": "text", "prompt": "Описание доп. кадров", "allowEmpty": true }
}
```

Основная колонка остаётся узкой: рамка рисуется у точки крепления, а не в общем ряду.

### Ссылка на шаг (`use`)

Нужна, когда тот же AI/ручной шаг нужен ещё раз в другом месте графа, без копипаста config.

```json
{
  "key": "extra_shots",
  "name": "Доп. шоты",
  "type": "ai",
  "use": "shot_generator",
  "dependsOn": ["extra_brief"],
  "iterate": null,
  "order": 12
}
```

- `use` — `key` исходного шага. Цепочки `use` нельзя замыкать.
- Свои у ссылки: `key`, `name`, `description`, `order`, `dependsOn`, `stopAfter`, `iterate`.
- Чужие (только у оригинала): `type` и `config`. В JSON ссылки `config` не пиши.
- Менять промпты и модель нужно в оригинале — ссылка подхватит сама.

## Переменные в текстах

В текстах сообщений, шаблонах и источниках можно писать `{{путь}}`.

| Путь | Что это |
| --- | --- |
| `{{inputs.topic}}` | Вход запуска |
| `{{steps.summary.output}}` | Весь результат шага |
| `{{steps.summary.output.ideas}}` | Поле внутри JSON-результата |
| `{{steps.summary.output.items[0].title}}` | Элемент массива и его поле |
| `{{prev.output}}` | Результат единственной прямой зависимости. Если зависимостей несколько, берётся та, что позже по графу |
| `{{globals.name}}` | Глобальная переменная проекта приложения |
| `{{project.name}}` | Переменная проекта |
| `{{current_item}}` | Текущий элемент ветки |
| `{{current_index}}` | Номер элемента ветки, с нуля |
| `{{idea}}` | То же, что элемент, если у ветки `alias` равен `idea` |
| `{{note}}` | Текст, который человек дописал к этому элементу, если задан `noteAlias` |
| `{{snippets.notes_block}}` | Фрагмент из корня workflow (`snippets`) |

Если весь текст — это одни скобки `{{steps.summary.output}}`, подставляется само значение: объект, массив или файл. Если скобки стоят внутри фразы, объект превращается в текст. Картинку в середину фразы так не вставить: для изображения нужен отдельный фрагмент `{{inputs.product_image}}` или весь текст равен этой ссылке.

Путь строится из имён, точек и индексов `[0]`. Имена такие же, как ключи: буква или `_`, дальше буквы, цифры и `_`.

### Условие `{{#if}}`

Блок текста можно показать только если значение заполнено:

```
Тема: {{inputs.topic}}
{{#if inputs.notes}}
Дополнительно:
{{inputs.notes}}
{{/if}}
```

- Открытие: `{{#if путь}}`, закрытие: `{{/if}}`. Вложенные блоки можно.
- «Заполнено»: непустая строка (не только пробелы), число, `true`, непустой массив, объект или файл. Пустая строка, `null`, `false` и `[]` — блок пропускается.
- Внутри блока обычные `{{путь}}` работают как обычно.
- Других директив нет (`{{#else}}` и подобное нельзя). Незакрытый `{{#if}}`, лишний `{{/if}}` или битый путь в условии — ошибка при проверке и сохранении workflow.

`{{#if}}` убирает кусок внутри одного текста. Чтобы не отправлять сообщение целиком, у сообщения AI-шага есть поле `when`.

### Фрагменты `snippets`

Повторяющийся кусок промпта вынеси в корень:

```json
"snippets": [
  {
    "key": "notes_block",
    "content": "{{#if inputs.notes}}\nДополнительно:\n{{inputs.notes}}\n{{/if}}"
  }
]
```

В сообщениях и шаблонах пиши `{{snippets.notes_block}}`. При подстановке содержимое фрагмента снова проходит через `{{...}}` и `{{#if}}`. Ключи фрагментов — как у входов: латиница, цифры и `_`.

## Шаг `ai`

Отправляет сообщения выбранной модели и сохраняет ответ. Если задана JSON-схема, ответ проверяется по ней. Исходный текст модели остаётся в запуске.

```json
{
  "key": "summary",
  "name": "Пересказ",
  "type": "ai",
  "config": {
    "provider": "openai",
    "model": "gpt-4.1-mini",
    "temperature": 0.3,
    "maxTokens": 800,
    "outputFormat": "text",
    "messages": [
      { "role": "system", "content": "Ты кратко пересказываешь текст." },
      { "role": "user", "content": "{{inputs.source_text}}" }
    ]
  }
}
```

| Поле config | Смысл |
| --- | --- |
| `provider` | Для `api` рабочий провайдер — `openai`. Если не указан, будет `openai`. Для `playwright` пиши `qwen` |
| `model` | Обязательная строка, имя модели. Для `playwright` можно `qwen`: модель выбирается в окне чата |
| `temperature` | Число, необязательно. В `playwright` не используется |
| `maxTokens` | Число, необязательно. В `playwright` не используется |
| `outputFormat` | `text` или `json`. По умолчанию `json` |
| `jsonSchema` | Объект JSON Schema. Имеет смысл при `outputFormat: "json"` |
| `messages` | Массив сообщений. У каждого `role`: `system`, `user` или `assistant`, и `content` — строка. Необязательное `when` решает, отправлять ли сообщение целиком |
| `chat` | Ключ чата из `chats`. Обязателен у AI-шага, когда `runtime` равен `playwright`. При `api` это поле писать нельзя |

`id` у сообщения не пиши. Роль `system` задаёт правила, `user` — запрос с данными, `assistant` — пример ответа, если он нужен.

`when` смотрит на переменные целиком. Нет `when` — сообщение уходит всегда. Если референса нет, сообщение с ним не попадает в запрос, остальные сообщения шага уходят как обычно.

```json
{ "role": "user", "content": "Референс:\n{{inputs.ref}}", "when": { "op": "and", "paths": ["inputs.ref", "inputs.pose"] } }
```

`op`: `and` — заполнены все пути из `paths`, `or` — достаточно одного. Путь пишется как внутри `{{ }}`, без скобок: `inputs.ref`, `steps.look.output`. Пустая строка, `null`, `false` и `[]` — переменной нет. Битый путь или условие без путей — ошибка проверки. Если условие не выполнилось ни у одного сообщения, шаг завершается ошибкой и в чат ничего не уходит.

В `playwright` у сообщений шага роль только `user`. Несколько таких сообщений уходят в чат по очереди: сначала фото и «это оригинал, запомни», затем следующее сообщение с референсом и задачей. Модель отвечает на каждое, шаг ждёт этот ответ и только потом шлёт следующее. Результат шага — ответ на последнее отправленное сообщение. Сообщение, которое `when` пропустил, в эту очередь не входит. Инструкция ассистента лежит в `chats`, а не в `system` шага. При `outputFormat: "json"` просьба вернуть JSON дописывается только к последнему сообщению, которое реально уходит.

При `outputFormat: "json"` проси модель вернуть объект по схеме. Следующие шаги читают поля как `{{steps.КЛЮЧ.output.поле}}`. Отдельный шаг разбора для этого обычно не нужен.

## Шаг `transform`

Меняет данные без модели: склеивает текст, достаёт поле, фильтрует массив или считает значение коротким скриптом.

`config.mode`:

| mode | Что делает | Поля |
| --- | --- | --- |
| `template` | Подставляет переменные в текст | `template` |
| `extract` | Возвращает значение по ссылке как есть, без превращения в строку | `source` |
| `filter` | Оставляет элементы массива | `source`, `field`, `op`, `value` |
| `script` | Выполняет тело функции. Доступен аргумент `ctx`. Нужно вернуть значение через `return` | `script` |

`op` для фильтра: `eq`, `neq`, `contains`, `truthy`. `field` — путь внутри элемента (`title` или `meta.lang`). Пустое `field` сравнивает сам элемент. `truthy` оставляет элементы, у которых значение непустое.

## Шаг `parse`

Разбирает уже готовый текст или JSON-строку в структуру. Если модель и так вернула JSON по схеме, этот шаг не нужен.

| `config.mode` | Смысл | Поля |
| --- | --- | --- |
| `json` | Разобрать JSON из текста. Если источник уже объект, он и будет результатом | `source` |
| `regex` | Найти все совпадения. Именованные группы `(?<name>...)` становятся полями объекта | `source`, `pattern` |
| `delimiter` | Разрезать текст. `delimiter` — строка, последовательность `\\n` в JSON означает перевод строки | `source`, `delimiter` |

`source` — ссылка, например `{{inputs.raw_list}}` или `{{prev.output}}`.

## Шаг `fanout`

Только раскладывает массив на ветки. Сам в модель ничего не отправляет. Результат этого шага внутри ветки — текущий элемент.

Шаги, которые зависят от него, идут внутри каждой ветки. Общим снова становится шаг `merge` с `mode: "collect"`, который собирает эти ветки.

```json
"iterate": { "over": "{{steps.ideas.output.ideas}}", "alias": "idea", "launch": "manual" }
```

| Поле | Смысл |
| --- | --- |
| `over` | Ссылка на массив. Пустой строкой оставлять нельзя |
| `alias` | Имя элемента: `{{idea}}` и `{{idea.title}}` |
| `launch` | `all` — все ветки сразу. Шаг запроса внутри каждой ветки стартует вместе с такими же шагами соседних веток, в том числе когда это ветвление вложено в другое. `sequence` — все ветки сами, но по очереди: следующая начинается, когда предыдущая завершилась. Очередь встаёт на ошибке. «Отсюда дальше» на этой ветке, если она завершилась, само запускает оставшиеся. Так ветки с одним чатом не пишут сообщения одновременно. `manual` — человек запускает по одной |
| `noteAlias` | Необязательно. Имя текста, который можно дописать к каждому элементу перед запуском. В шаге и внутри его веток он читается как `{{это_имя}}` |
| `appendOnRerun` | `true` — повтор с другим массивом добавляет новый ряд. Массив, который совпадает с уже созданным рядом, ряд не копирует |

`config` у этого шага пустой. Поле `iterate` обязательно.

Элемент также доступен как `{{steps.КЛЮЧ_FANOUT.output}}` и как `{{current_item}}`.

Если тот же массив сформировали ещё раз, новый ряд не создаётся: ветки уже есть. Другой массив при том же числе элементов по умолчанию обновляет текущие ветки на месте. `"appendOnRerun": true` и галочка «Новый ряд» на запуске добавляют другой массив следующим рядом.

## Шаг `manual`

Останавливает ветку и ждёт человека.

| `config.mode` | Что делает человек |
| --- | --- |
| `select_one` | Выбирает один элемент |
| `select_many` | Выбирает несколько |
| `text` | Вводит или правит текст |
| `confirm` | Подтверждает результат |
| `edit_json` | Правит JSON |
| `upload_image` | Загружает изображение |
| `upload_file` | Загружает файл |

| Поле | Смысл |
| --- | --- |
| `prompt` | Текст вопроса. Можно пустую строку |
| `source` | Что показать или откуда взять варианты, обычно `{{steps.previous.output}}` |
| `labelField` | Какое поле объекта показать как название варианта, например `title` |
| `descriptionField` | Какое поле показать как пояснение |
| `allowEmpty` | `true` — можно ничего не выбрать или оставить текст пустым |
| `skipStepIds` | Ключи шагов, которые не выполнять, если на запуске нажать «Пропустить». Обычно следующий AI, который должен учесть ответ человека |

Для выбора из массива объектов указывай `source`, `labelField` и при необходимости `descriptionField`. Результат выбора читается как `{{steps.КЛЮЧ.output}}`.

## Шаг `merge`

Собирает результаты в один объект, чтобы следующий шаг получил их вместе.

`mode: "object"` — явно названные куски:

```json
{
  "mode": "object",
  "sources": [
    { "key": "summary", "ref": "{{steps.summary.output}}" },
    { "key": "notes", "ref": "{{inputs.notes}}" }
  ]
}
```

`key` — поле в собранном объекте. `ref` — ссылка на значение.

`mode: "collect"` — собрать результаты веток одного fanout:

```json
{
  "mode": "collect",
  "fromFanoutStepId": "each_idea",
  "fromStepId": "pitch"
}
```

Оба поля — ключи шагов. `fromFanoutStepId` — шаг `fanout`. `fromStepId` — шаг внутри его веток, чей результат нужно собрать в массив. Этот шаг сборки должен быть в `dependsOn` у самого себя от fanout: `"dependsOn": ["each_idea"]`.

## Шаг `input`

Кладёт выбранные входы запуска в один объект. Нужен, когда дальше надо отдать не все входы, а только часть.

```json
{ "keys": ["topic", "source_text"] }
```

`keys` — это `name` входов, не их `id`. Результат — объект `{ "topic": ..., "source_text": ... }`.

## Ветвление на обычном шаге

У шага, который не `fanout`, можно включить старый режим: `"iterate": { "over": "...", "alias": "item", "launch": "all" }`. Тогда этот же шаг выполнится отдельно для каждого элемента. Для новой схемы так не делай: сначала шаг `fanout`, потом обычные шаги, в конце `merge` с `mode: "collect"`.

## Пример: текст и проверка человеком

```json
{
  "name": "Краткий пересказ",
  "description": "Один ответ модели и подтверждение",
  "inputs": [
    {
      "name": "source_text",
      "label": "Текст",
      "type": "text",
      "required": true,
      "description": "Что пересказать"
    }
  ],
  "steps": [
    {
      "key": "summary",
      "name": "Пересказ",
      "type": "ai",
      "config": {
        "provider": "openai",
        "model": "gpt-4.1-mini",
        "temperature": 0.3,
        "outputFormat": "text",
        "messages": [
          { "role": "system", "content": "Ты кратко пересказываешь текст на том же языке." },
          { "role": "user", "content": "{{inputs.source_text}}" }
        ]
      }
    },
    {
      "key": "approve",
      "name": "Проверка",
      "type": "manual",
      "dependsOn": ["summary"],
      "config": {
        "mode": "confirm",
        "prompt": "Пересказ годится?",
        "source": "{{steps.summary.output}}"
      }
    }
  ]
}
```

## Пример: JSON, ветки и сборка

Модель возвращает массив идей. Шаг `fanout` запускает питч для каждой. `merge` собирает питчи обратно в один массив.

```json
{
  "name": "Идеи и питчи",
  "description": "Список идей, отдельный текст на каждую и сборка",
  "inputs": [
    {
      "name": "topic",
      "label": "Тема",
      "type": "string",
      "required": true,
      "description": ""
    }
  ],
  "steps": [
    {
      "key": "ideas",
      "name": "Идеи",
      "type": "ai",
      "config": {
        "model": "gpt-4.1-mini",
        "outputFormat": "json",
        "jsonSchema": {
          "type": "object",
          "additionalProperties": false,
          "required": ["ideas"],
          "properties": {
            "ideas": {
              "type": "array",
              "items": {
                "type": "object",
                "additionalProperties": false,
                "required": ["title"],
                "properties": {
                  "title": { "type": "string" }
                }
              }
            }
          }
        },
        "messages": [
          { "role": "user", "content": "Предложи идеи на тему {{inputs.topic}}. Верни JSON по схеме." }
        ]
      }
    },
    {
      "key": "each_idea",
      "name": "Каждая идея",
      "type": "fanout",
      "dependsOn": ["ideas"],
      "iterate": {
        "over": "{{steps.ideas.output.ideas}}",
        "alias": "idea",
        "launch": "manual"
      }
    },
    {
      "key": "pitch",
      "name": "Питч",
      "type": "ai",
      "dependsOn": ["each_idea"],
      "config": {
        "model": "gpt-4.1-mini",
        "outputFormat": "text",
        "messages": [
          { "role": "user", "content": "Напиши один абзац про {{idea.title}}" }
        ]
      }
    },
    {
      "key": "all_pitches",
      "name": "Все питчи",
      "type": "merge",
      "dependsOn": ["each_idea"],
      "config": {
        "mode": "collect",
        "fromFanoutStepId": "each_idea",
        "fromStepId": "pitch"
      }
    }
  ]
}
```

## Пример: разбор текста, выбор и шаблон

```json
{
  "name": "Список",
  "description": "Разрезать текст, выбрать пункты и собрать их обратно",
  "inputs": [
    {
      "name": "raw_list",
      "label": "Список",
      "type": "text",
      "required": true,
      "description": "Пункты через пустую строку"
    }
  ],
  "steps": [
    {
      "key": "lines",
      "name": "Пункты",
      "type": "parse",
      "config": {
        "source": "{{inputs.raw_list}}",
        "mode": "delimiter",
        "delimiter": "\\n\\n"
      }
    },
    {
      "key": "pick",
      "name": "Выбор",
      "type": "manual",
      "dependsOn": ["lines"],
      "config": {
        "mode": "select_many",
        "source": "{{steps.lines.output}}",
        "prompt": "Оставьте нужные пункты",
        "allowEmpty": false
      }
    },
    {
      "key": "chosen_inputs",
      "name": "Исходный список",
      "type": "input",
      "dependsOn": ["pick"],
      "config": { "keys": ["raw_list"] }
    },
    {
      "key": "joined",
      "name": "Текст",
      "type": "transform",
      "dependsOn": ["pick", "chosen_inputs"],
      "config": {
        "mode": "template",
        "template": "Выбрано:\n{{steps.pick.output}}"
      }
    }
  ]
}
```
