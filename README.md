# AI Workflow Pipeline

Настольное приложение для сборки и запуска AI-workflow. Первый провайдер — OpenAI. Движок не знает деталей конкретного API: шаг просит `AIProvider`, а реализацию можно добавить отдельно.

## Запуск

```bash
npm install
npm test
npm run dev
```

Ключ OpenAI задаётся в меню «Файл → Настройки». Он шифруется через `safeStorage` Electron и остаётся в main-процессе. React к API модели не обращается.

Данные лежат в каталоге userData Electron: `pipeline.sqlite`, `secrets.bin` и папка `media`.

## Как устроено

```text
Project → Workflow → WorkflowVersion → Steps
Project → Run → StepExecution / Branch → Artifact
```

- Workflow — граф шагов (`dependsOn`), а не жёсткий сценарий.
- Сохранение workflow создаёт новую версию. Старый запуск ссылается на ту версию, с которой стартовал.
- Запуск хранит входы, попытки шагов, сырой ответ модели, разобранный результат и ветки.
- Повтор шага добавляет новую попытку и не стирает предыдущую.
- Массив можно обработать «для каждого элемента». Ветки запускаются все сразу или вручную, по одной.
- Ручной шаг переводит выполнение в `waiting_for_user`. После выбора продолжается только эта ветка.

Типы шагов MVP: AI, преобразование, разбор, ручной шаг, сборка, вход.

Шаблон «Пример Neurophoto» собирает сценарий из спецификации: идентификаторы продукта, паспорт, концепции, выбор, кадры, отбор кадров и JSON-промпт. Промпт для кадра запускается отдельно для каждой выбранной ветки.

## Куда добавлять провайдер

Интерфейс `AIProvider` и реестр в `src/main/providers.ts`. Сейчас реализован `OpenAIProvider`. Anthropic, Google и SYNTX видны в настройках как следующие точки расширения.
